# ЧАСТЬ 7 - Сайт на VPS, домен и фотоархив Immich с доступом из интернета

> **Что получится:**
> - свой домен, на нём обычный сайт (например, семейный фото-блог) с HTTPS;
> - на поддомене `photos.` - вход в **Immich**: свой "Google Фото", который
>   работает дома, а открывается из любой точки мира по ссылке в браузере и
>   в приложении на телефоне. Без VPN у пользователей;
> - фото лежат **дома**, VPS только передаёт трафик по туннелю.
>
> **Нужно заранее:** VPS с AmneziaWG и шлюз дома с пиром на VPS (Части 2 и 6).
>
> **Правила для ИИ - в Части 0.** Всегда называй машину: **ПК**, **VPS**,
> **шлюз** (дома). Пароли и ключи в чат не присылаются.
>
> В тексте `example.com` - **пример**. ⛔ Везде подставляй свой домен.

---

## Схема

```
 Браузер / приложение Immich (где угодно)
        │  https://example.com            https://photos.example.com
        ▼
   VPS: Caddy (HTTPS, сертификаты сам)
        │ сайт: файлы с диска VPS         │ photos: reverse_proxy
        │                                 ▼   по туннелю AmneziaWG
        │                           10.78.0.6:2283  (шлюз дома, vpn-backup)
        ▼                                 │
   страницы сайта                   Immich в Docker на шлюзе
                                    фото на диске дома
```

Почему так:
- дома обычно нет белого IP, а провайдер может закрывать входящие
  порты. Туннель идёт **от** дома к VPS, входящие дома не нужны;
- домашний IP нигде не светится: в DNS указан адрес VPS;
- если упал туннель, сайт работает, а `photos.` временно недоступен.

### Сайт как "лицо" VPS (маскировка)

VPS без сайта выглядит странно: адрес, на котором ничего не отвечает на
80/443, зато идёт поток UDP. С сайтом VPS для любого, кто на него
посмотрит (сканер, браузер, проверка по IP), - **обычный веб-хостинг**:
домен, настоящий сертификат HTTPS, живые страницы. А Immich на `photos.`
даёт настоящий, объёмный HTTPS-трафик (фото, видео) на тот же адрес.

Честно о границах:
- сайт **не прячет** сам туннель AmneziaWG - тот идёт отдельно, по своему
  UDP-порту, и маскируется своими параметрами (Часть 6). Сайт меняет то,
  как выглядит **сервер целиком**;
- маскировка работает, только если сайт похож на настоящий: свои тексты и
  фото, несколько страниц, иногда обновлять. Пустая страница-заглушка или
  стандартная страница веб-сервера выдают "технический" сервер;
- ни один способ не даёт гарантии от блокировки. Это снижение заметности,
  а не броня.

Что сделать, чтобы сайт выглядел живым:
- реальный шаблон и своё содержимое (шаг 7.5), а не "It works";
- своя страница 404 (`404.html` в корне сайта);
- `www.` перенаправляет на основной домен (так делают почти все сайты);
- кнопка "Войти" ведёт на `photos.` - сайт и фотоархив выглядят как одно
  целое.

## Шаг 7.1 - Купить домен

Подойдёт любой регистратор. Что учесть:

| | Российский регистратор, зона `.ru`/`.рф` | Иностранный регистратор, `.com/.net/.top` и др. |
|---|---|---|
| документы | паспортные данные обязательны | обычно только email |
| оплата | российские карты | часто нужна иностранная карта или крипта |
| DNS | у регистратора, бесплатно | у регистратора, бесплатно |

Советы:
- бери сразу на 2-3 года: продление обычно дороже первой покупки;
- включи **автопродление** или поставь напоминание - потерянный домен
  перехватывают;
- если есть опция защиты WHOIS (скрытие данных владельца) - включи.

## Шаг 7.2 - DNS: направить домен на VPS

В панели регистратора, раздел DNS (или "Управление зоной"). NS-серверы
оставь регистратора - менять их не нужно.

Создай три записи типа **A** (⛔ IP - внешний адрес твоего VPS):

| Имя (Host) | Тип | Значение | TTL |
|---|---|---|---|
| `@` | A | IP VPS | 3600 (или по умолчанию) |
| `www` | A | IP VPS | 3600 |
| `photos` | A | IP VPS | 3600 |

`@` - сам домен `example.com`, `www` - `www.example.com`, `photos` -
`photos.example.com`.

**Проверка с ПК** (PowerShell), через 5-60 минут после сохранения:

```
nslookup photos.example.com 8.8.8.8
```

**ОЖИДАЕТСЯ:** в ответе `Address:` с IP твоего VPS.

**ЕСЛИ старый адрес или "не найден"** -> подожди ещё (до нескольких часов) и
проверь, что записи сохранились в панели. Сертификат на шаге 7.6 получится
только после того, как DNS указывает на VPS.

## Шаг 7.3 - Открыть 80/443 на VPS

Caddy нужен порт 80 (получение сертификата) и 443 (HTTPS).

⚠️ Помни Часть 6: `/etc/nftables.conf` начинается с `flush ruleset`, на
живом сервере файл целиком **не применять**. Правило - живой командой и
той же строкой в файл.

**На VPS.** Посмотреть, есть ли уже правило:

```
nft list chain inet filter input | grep -E '80|443'
```

Нет - добавь вживую:

```
nft insert rule inet filter input tcp dport { 80, 443 } accept
```

```
nft insert rule inet filter input udp dport 443 accept
```

И в файл: открой `nano /etc/nftables.conf`, в цепочку `input` рядом с
другими `accept` впиши две строки:

```
        tcp dport { 80, 443 } accept
        udp dport 443 accept
```

```
nft -c -f /etc/nftables.conf && echo OK
```

**ОЖИДАЕТСЯ:** `OK` (только проверка синтаксиса, ничего не применяется).

## Шаг 7.5 - Шаблон сайта

Готовые бесплатные шаблоны (чистый HTML/CSS, без серверной части):
- **HTML5 UP** (html5up.net) - красивые, лицензия CC BY 3.0: **ссылку на
  автора в подвале оставить обязательно**;
- **Start Bootstrap** (startbootstrap.com) - лицензия MIT.

На **ПК**:
1. Скачай архив шаблона, распакуй в папку, например `C:\site`.
2. Открой `index.html` в Блокноте (или VS Code), замени тексты и картинки
   на свои. Картинки - в папку `images`.
3. Добавь кнопку входа в фотоархив, рядом с меню или в шапке (⛔ свой домен):

```
<a href="https://photos.example.com" class="button">Войти</a>
```

4. Открой `index.html` в браузере - посмотри, как выглядит.

**На VPS** - папка сайта:

```
mkdir -p /var/www/site
```

**На ПК** (PowerShell) - залить файлы (⛔ адрес VPS - как ты к нему
подключаешься: Tailscale или `10.78.0.1` через туннель):

```
scp -r C:\site\* root@АДРЕС_VPS:/var/www/site/
```

**На VPS** - права (Caddy читает файлы от своего пользователя):

```
chown -R root:root /var/www/site
```

```
chmod -R a+rX /var/www/site
```

```
ls /var/www/site
```

**ОЖИДАЕТСЯ:** `index.html` и папки шаблона.

## Шаг 7.6 - Конфиг Caddy: сайт, защита, вход в Immich

Бэкап стандартного конфига:

```
cp /etc/caddy/Caddyfile /root/Caddyfile.orig
```

⛔ Замени `example.com` на свой домен (5 мест) и `ПОДСТАВЬ_TS_ШЛЮЗА` на
Tailscale-адрес шлюза (`tailscale ip -4` на шлюзе). Если на VPS нет
Tailscale - удали из строки `reverse_proxy` второй адрес целиком.

```
tee /etc/caddy/Caddyfile > /dev/null <<'EOF'
# Общие заголовки безопасности
(security) {
    header {
        -Server
        Strict-Transport-Security "max-age=31536000"
        X-Content-Type-Options "nosniff"
        X-Frame-Options "DENY"
        Referrer-Policy "strict-origin-when-cross-origin"
    }
    log
}

# Основной сайт
example.com {
    import security
    root * /var/www/site
    encode zstd gzip
    # скрытые файлы (.git, .env и т.п.) - не отдавать
    @hidden path */.*
    respond @hidden 404
    # картинки, стили, скрипты - кэш в браузере на неделю
    @static path *.jpg *.jpeg *.png *.webp *.gif *.svg *.css *.js
    header @static Cache-Control "public, max-age=604800"
    file_server
    # своя страница "не найдено"
    handle_errors {
        @notfound expression {err.status_code} == 404
        rewrite @notfound /404.html
        file_server
    }
}

# www -> без www
www.example.com {
    redir https://example.com{uri} permanent
}

# Фотоархив Immich: по туннелю к шлюзу дома, запасной путь - Tailscale
photos.example.com {
    import security
    reverse_proxy 10.78.0.6:2283 ПОДСТАВЬ_TS_ШЛЮЗА:2283 {
        lb_policy first
        lb_try_duration 5s
        fail_duration 30s
        transport http {
            read_timeout 600s
            write_timeout 600s
        }
    }
}
EOF
```

Если в шаблоне нет `404.html`, создай простую:

```
echo '<!doctype html><meta charset="utf-8"><title>Страница не найдена</title><h1>Страница не найдена</h1><p><a href="/">На главную</a></p>' > /var/www/site/404.html
```

> Что тут сделано:
> - **сертификаты HTTPS** Caddy получает и продлевает сам (Let's Encrypt);
> - `-Server` - не сообщает, какой сервер работает;
> - `Strict-Transport-Security` - браузер ходит только по HTTPS;
> - `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy` - защита от
>   подмены типа файла, встраивания во чужие страницы и утечки адресов;
> - `file_server` **без** `browse` - список файлов в папках не показывается;
> - скрытые файлы отдают 404;
> - `log` - журнал всех запросов в journald (шаг 7.11);
> - заголовки `X-Forwarded-For`/`X-Forwarded-Proto` для Immich Caddy ставит
>   сам; ограничения на размер загрузки у Caddy по умолчанию нет; таймауты
>   600 с - чтобы не рвались загрузки больших видео (как советует
>   документация Immich);
> - `10.78.0.6` - адрес шлюза в туннеле (Часть 6). Если твой шлюз в
>   туннеле под другим адресом - подставь его;
> - **два адреса в `reverse_proxy`**: `lb_policy first` - всегда первый
>   (туннель AmneziaWG), а если он не отвечает - через 5 с пробует второй
>   (Tailscale) и 30 с считает первый упавшим. Фотоархив переживает обрыв
>   основного туннеля.

Проверка и применение:

```
caddy validate --config /etc/caddy/Caddyfile
```

**ОЖИДАЕТСЯ:** `Valid configuration`.

```
systemctl reload caddy
```

```
journalctl -u caddy -n 30 --no-pager | grep -iE 'certificate|error'
```

**ОЖИДАЕТСЯ:** строки `certificate obtained successfully` для каждого
домена. Ошибки про `challenge` - DNS ещё не указывает на VPS (7.2) или
закрыт порт 80 (7.3).

**Проверка с ПК:** открой `https://example.com` - сайт с замком в адресной
строке. `https://photos.example.com` пока выдаст ошибку 502 - Immich ещё не
установлен (следующие шаги).

## Шаг 7.7 - Docker на шлюзе (для Immich)

Immich ставится на **машину, где лежат фото** - здесь на шлюз дома. Нужен
отдельный диск под фото (системный SSD шлюза маленький и не для этого).
Пусть диск примонтирован в `/mnt/photos`. Как выбрать, разметить и
подключить диск - **Часть 8, шаги 8.1-8.5**. Сделай это до установки.

По [документации Immich](https://docs.immich.app/install/docker-compose)
нужен официальный Docker Engine (пакет `docker.io` из репозитория бывает
слишком старым). Официальный установочный скрипт Docker, **на шлюзе**:

```
curl -fsSL https://get.docker.com -o /tmp/get-docker.sh
```

```
sudo sh /tmp/get-docker.sh
```

```
docker compose version
```

**ОЖИДАЕТСЯ:** `Docker Compose version v2...`.

⚠️ **Проверь, что шлюз всё ещё раздаёт интернет.** Docker при установке
может поставить политику цепочки `FORWARD` в `DROP`, и клиенты LAN потеряют
интернет. Обычно этого не происходит, если пересылка (`ip_forward`) уже была
включена до Docker (Часть 1), но проверь сразу с клиента: открывается ли
сайт. И на шлюзе:

```
sudo iptables -L FORWARD -n | head -1
```

**ЕСЛИ клиенты без интернета и там `policy DROP`** ->
`sudo iptables -P FORWARD ACCEPT` и сообщи помощнику: нужно закрепить
настройку, чтобы она пережила перезагрузку.

## Шаг 7.8 - Установить Immich

**На шлюзе:**

```
mkdir -p ~/immich && cd ~/immich
```

```
wget -O docker-compose.yml https://github.com/immich-app/immich/releases/latest/download/docker-compose.yml
```

```
wget -O .env https://github.com/immich-app/immich/releases/latest/download/example.env
```

Настройки:

```
nano ~/immich/.env
```

Поменяй (⛔ свои значения):

| Строка | Значение | Зачем |
|---|---|---|
| `UPLOAD_LOCATION=` | `/mnt/photos/immich` | где лежат фото и видео |
| `DB_DATA_LOCATION=` | `./postgres` | база; на локальном диске, **не** на сетевой папке |
| `TZ=` | раскомментировать, `Europe/Moscow` | часовой пояс |
| `DB_PASSWORD=` | длинный, только буквы и цифры | пароль базы |

И **добавь** строку в конец:

```
IMMICH_HOST=0.0.0.0
```

> Зачем: на шлюзе IPv6 выключен (Часть 1), а один из контейнеров Immich по
> умолчанию пытается слушать IPv6 и падает в цикле перезапусков. Эта строка
> заставляет его слушать только IPv4. Реальный случай.

Сохрани (Ctrl+O, Enter, Ctrl+X). Папка для фото:

```
sudo mkdir -p /mnt/photos/immich
```

Запуск:

```
cd ~/immich && sudo docker compose up -d
```

**ОЖИДАЕТСЯ:** скачивание образов (несколько минут), затем `Started` у
каждого контейнера.

```
sudo docker compose ps
```

**ОЖИДАЕТСЯ:** `immich_server`, `immich_machine_learning`, база и redis -
все `Up` (у некоторых `(healthy)`).

**ЕСЛИ `can't set healthcheck.start_interval`** -> старый Docker. В
`docker-compose.yml` закомментируй строку `start_interval` в разделе
`database` и повтори запуск.

## Шаг 7.9 - Закрыть порт Immich от WAN

Docker открывает опубликованные порты **мимо** нашей цепочки `input`:
трафик к контейнеру идёт через `forward`. Поэтому `2283` по умолчанию
доступен с любого интерфейса шлюза, включая `wan`. За PON-терминалом это не
критично (его NAT прикрывает), но **обязательно**, если терминал когда-нибудь
переведут в мост, включат DMZ на шлюз или WAN станет белым адресом: тогда
Immich окажется открыт всему интернету.

Бэкап (на **шлюзе**):

```
sudo cp /etc/gw-fw.nft /etc/gw-fw.nft.bak-2283
```

Строка-якорь (MSS clamp) должна быть в файле ровно одна:

```
sudo grep -n "maxseg" /etc/gw-fw.nft
```

**ОЖИДАЕТСЯ:** одна строка. ⛔ Больше одной - СТОП, вставка задвоится.

Вставить правило после неё:

```
sudo sed -i '/maxseg size set rt mtu/a\        iifname "wan" tcp dport 2283 drop' /etc/gw-fw.nft
```

Проверить синтаксис, ничего не применяя:

```
sudo nft -c -f /etc/gw-fw.nft
```

**ОЖИДАЕТСЯ:** пустой вывод. Применить:

```
sudo nft -f /etc/gw-fw.nft
```

```
sudo nft list chain inet gw_fw forward
```

**ОЖИДАЕТСЯ:** строка `iifname "wan" tcp dport 2283 drop`.

LAN, Tailscale и туннель от VPS (`vpn-backup`) продолжат работать.

> Как проверить, что закрыто: `sudo nft list ruleset | grep 2283`. Правило
> DNAT от Docker (`dnat to 172.x.x.x:2283`) там будет всегда - это нормально.
> Важно, чтобы было и наше `drop` для `wan`.

## Шаг 7.10 - Первая настройка Immich

1. Из дома открой `http://192.168.50.1:2283` (или Tailscale-адрес шлюза
   `:2283`). Создай **администратора** - первый зарегистрированный
   пользователь становится админом.
2. Администрирование -> Настройки -> **Настройки сервера** -> **Внешний
   домен** (External domain): `https://photos.example.com`. Без этого
   ссылки "поделиться" будут вести на внутренний адрес.
3. Администрирование -> **Пользователи** -> **Создать пользователя** -
   учётка каждому члену семьи. Сам зарегистрироваться посторонний не может:
   регистрация только через админа. Поля:
   - **Email** - это и есть логин. Настоящей почты не нужно: Immich никуда
     не пишет, пока не настроена отправка писем. Например `mama@example.com`;
   - **Пароль** - временный, его придумывает админ и передаёт человеку;
   - включи **"Требовать смену пароля при первом входе"** - тогда
     постоянный пароль знает только сам человек;
   - **Квота** в GiB (100 GiB ≈ 107 ГБ), чтобы один человек не забил диск.

   Человеку передаёшь три вещи: адрес `https://photos.example.com`, email и
   временный пароль.
   > Переключатель **"Публичные пользователи"** (Настройки сервера): включён -
   > все видят имена и email-логины друг друга в общих альбомах; выключен -
   > делиться можно только ссылкой.
4. Проверь снаружи: `https://photos.example.com` - страница входа Immich.
   Кнопка "Войти" на сайте ведёт сюда же.

**Приложение на телефоне** (Immich в Google Play / App Store):
- адрес сервера: `https://photos.example.com` - **внешний**, тогда
  работает и дома, и вне дома;
- Tailscale-адрес работает только при включённом Tailscale на телефоне -
  реальный случай "не грузит вне дома".

## Шаг 7.11 - Журнал и проверка безопасности

Журнал запросов (на **VPS**):

```
journalctl -u caddy --since "1 hour ago" --no-pager | tail -20
```

Каждая загрузка фото в Immich видна так:

```
journalctl -u caddy --since today --no-pager | grep '"uri":"/api/assets"' | tail -5
```

В записи: `status` (код ответа), `bytes_read` (сколько принято), `duration`.
`status 499` - соединение закрыл **клиент** (приложение, браузер), а не
сервер.

Проверка заголовков снаружи (с **ПК**, PowerShell):

```
curl.exe -sI https://example.com
```

**ОЖИДАЕТСЯ:** `HTTP/1.1 200`, есть `strict-transport-security`,
`x-frame-options`, **нет** строки `server:`.

Что знают о VPS сканеры:

```
curl.exe -s https://internetdb.shodan.io/IP_VPS
```

Поисковики: Immich сам отдаёт `robots.txt` с запретом индексации (кроме
публичных ссылок "поделиться"). Сам сайт индексируется как обычно.

## Шаг 7.12 - Бэкап и обновление Immich

Готовый скрипт бэкапа со снимками и таймером - **Часть 8, шаг 8.7**.

**Что бэкапить:** папку `UPLOAD_LOCATION` (фото и видео) и **базу**
(альбомы, лица, пользователи). Без базы фото останутся, но вся структура
пропадёт. В настройках Immich (Администрирование -> Настройки) есть
автоматическое резервное копирование базы - проверь, что оно включено и куда
пишет. Копию фото держи на **другом диске**, лучше и вне дома.

> ⚠️ Реальная грабля: бэкап, который делает `rsync --delete` **из копии в
> живую библиотеку** (перепутаны источник и цель), каждую ночь откатывает
> библиотеку назад. Проверяй, что источник в скрипте бэкапа - именно папка,
> которую реально использует контейнер:
> `sudo docker inspect immich_server | grep -A3 '"Destination": "/data"'`.

**Обновление** (читай заметки к релизу на GitHub перед крупным
обновлением):

```
cd ~/immich && sudo docker compose pull
```

```
cd ~/immich && sudo docker compose up -d
```

```
sudo docker compose ps
```
