# ЧАСТЬ 10 - Сборка шлюза с нуля: что делаешь ты, что делает ИИ-агент

> **Сценарий:** ты покупаешь железо и сам делаешь только то, что не может
> сделать программа (деньги, аккаунты, кабели, входы по ссылке). Всё
> остальное - установку, туннели, VPS, пул WARP, полосы, скрипты - ведёт
> ИИ-агент по Частям 1-9, этапами и с остановками. На выходе - готовый
> шлюз без граблей, на которые уже наступили на Стелле.
>
> ⚠️ **Статус: схема не обкатана.** Ни один шлюз пока не собран агентом от
> начала до конца. Перед боевой сборкой прогони её на тестовой машине
> (раздел 8). Части 1-9 проверены на живых шлюзах, а вот "агент проходит их
> без человека" - нет.
>
> Здесь нет новых скриптов и команд. Часть 10 - это **порядок, границы и
> точки останова**; сами команды берутся из Частей 1-9.

---

## 1. Разделение ролей

Обозначения: 👤 - делаешь ты, 🤖 - делает агент, ⛔ - агент обязан остановиться
и ждать тебя.

| Что | Кто | Почему |
|---|---|---|
| купить и собрать железо, поставить Debian, кабели, BIOS | 👤 | физика |
| деньги: VPS, домен, подписки | 👤 | платежи |
| войти по ссылке (Tailscale), создать бота, токен | 👤 | твои аккаунты, секреты |
| записи DNS у регистратора | 👤 | твой аккаунт |
| логин и пароль PPPoE (если шлюз заменяет роутер) | 👤 | секрет |
| выбрать, какие диски стереть | 👤 | необратимо |
| пакеты, сеть, firewall, NAT, DHCP, DNS (Часть 1) | 🤖 | по шагам, с проверками |
| AmneziaWG, слоты, полосы, оркестратор (Часть 2) | 🤖 | то же |
| VPS: сервер, firewall, пиры (Часть 6) | 🤖 | по SSH-ключу, который ты дал |
| WARP: регистрация, пул, пересадка (Части 2, 5) | 🤖 | ключи остаются на шлюзе |
| Caddy, Immich, диски, бэкапы (Части 7-8) | 🤖 | после твоего подтверждения дисков |
| проверка, учения, отчёт | 🤖 | и сверка `docs-drift` |

**Чего агенту не давать никогда:** содержимое `/etc/gateway/tg.conf`, ключей
WARP, `PresharedKey`, паролей, клиентских `.conf`. Агент пишет скрипт и
запускает его, а секрет читает только сам скрипт. Это правило 9 из Части 0.

## 2. Доверие и права агента

На время сборки агенту нужен широкий `sudo` (он пишет в `/etc`, ставит
пакеты, управляет службами): ограниченный список команд здесь не сработает.
Поэтому действует схема "временный доступ":

1. 👤 Заведи на шлюзе отдельного пользователя `agent` с входом **только по
   ключу** и `sudo`. Ключ - отдельный, не твой основной.
2. 👤 Для VPS - отдельный SSH-ключ `agent-vps`, тоже по отдельному
   пользователю или с `root` по ключу (Часть 6, Шаг 6.1).
3. После приёмки (раздел 7) 🤖/👤: заблокировать пользователя (`usermod -L
   agent`, убрать ключ из `authorized_keys`), убрать ключ с VPS. Агент больше
   доступа не имеет; если нужна правка - выдаёшь снова.
4. Все команды агента логируются: `sudo` пишет в журнал (`journalctl
   _COMM=sudo`), плюс агент ведёт свой журнал шагов (раздел 5).

**Секреты и облачный агент.** Если агент - облачная модель, всё, что он
прочитал (вывод `cat`, переменные), уходит провайдеру модели. Тогда
секреты (`tg.conf`, пароль PPPoE) 👤 кладёшь **после** сборки сам, а до этого
служба-пустышка шлёт уведомления в никуда. Если модель локальная, секреты
можно класть на точках останова, но вывод всё равно режем (правило 9).

## 3. Часть А - чек-лист владельца (👤)

Выполняй по порядку. У каждого пункта - как сделать и чем закончить.

### А0. Железо и BIOS

- Подбери по Части 1 ("Что нужно из железа"). Если шлюз будет стоять без
  тебя - там же заметка про AMT и KVM: решай **сейчас**.
- В BIOS: **Restore on AC Power Loss = Power On**; включить аппаратный
  watchdog, если он есть; порядок загрузки: сначала диск (флешку GRUB потом
  - Часть 8, Шаг 8.11).
- Диски: реши роли заранее (Часть 8, Шаг 8.0), подключи.
- **Готово, когда:** машина включается сама после пропажи света.

### А1. Debian 13

- Поставь Debian 13 по Части 1, Шаг 1.1: минимальная система, SSH-сервер,
  без графики, с отдельным пользователем.
- Подключи **обе** сетевые карты, WAN в сторону провайдера, LAN в свитч.
- Запиши: MAC обеих карт (`ip -br link`), какая куда воткнута.
- **Готово, когда:** ты заходишь на шлюз по SSH из LAN.

### А2. Доступ для агента

- Создай пользователя `agent` и положи его ключ (раздел 2, пункт 1).
- Проверь вход ключом в новом окне **до** того, как отключать пароли
  (Часть 2, Шаг 2.16).
- **Готово, когда:** агент (или ты за него) входит `ssh agent@шлюз` без пароля
  и выполняет `sudo -n true`.

### А3. VPS (если нужен)

- Выбери хостера по Части 6, Шаг 6.1: **проверь до оплаты** (тестовый период,
  SSH из дома, адрес не в блок-листах, ОС - `cat /etc/os-release`).
- После покупки: IP, доступ по ключу `agent-vps`; пароль root из письма
  хостера смени сразу и никому не присылай.
- **Готово, когда:** `ssh -i agent-vps root@IP` работает с шлюза.

### А4. Telegram-бот

- В Telegram открой `@BotFather`, команда `/newbot`, получи **токен**.
- Свой chat id узнай у `@userinfobot`.
- Напиши своему боту любое слово (иначе он не сможет тебе писать).
- Токен и chat id сохрани у себя. В чат с агентом **не присылай**.
- Файл `/etc/gateway/tg.conf` создашь сам в точке останова С2.

### А5. Tailscale

- Аккаунт Tailscale (бесплатного хватает). В точке останова С1 агент покажет
  **ссылку** входа: открой её в браузере и подтверди.
- Если шлюз будет стоять **не у тебя**: в панели Tailscale (Access controls)
  пометь его тегом и настрой правило так, чтобы ты мог подключаться к нему,
  а он к твоим устройствам - нет. ⚠️ В документации это пока не описано
  по шагам (пробел, см. раздел 11), делается руками в панели.

### А6. Домен (только для сайта и Immich)

- Купи домен по Части 7, Шаг 7.1, **после** того как известен IP VPS.
- В панели регистратора создай три записи A (`@`, `www`, `photos`) на IP VPS
  (Часть 7, Шаг 7.2).
- Проверь с ПК: `nslookup photos.твойдомен 8.8.8.8` - в ответе IP VPS.
- **Готово, когда:** проверка выше дала нужный IP. Без этого сертификат
  (Часть 7, Шаг 7.6) не получится, агент не должен идти дальше.

### А7. PPPoE (если шлюз заменяет роутер провайдера)

- Логин и пароль PPPoE - из договора или у провайдера. По Части 9 (Шаг 9.0)
  реши, подходит ли твоё подключение. Пароль 👤 вносишь сам на точке
  останова С5, агенту не передаёшь.

### А8. Клиенты

- Wi-Fi-роутер или точка доступа - в режиме **AP** (без своего DHCP, без
  двойного NAT), включена в LAN-порт.
- Не включай VPN и Secure DNS на устройствах (Часть 4, раздел 2).

## 4. Паспорт сборки

Это файл **без секретов**, который заполняешь ты и читает агент. Из него
агент берёт всё, что в Частях 1-9 помечено `ПОДСТАВЬ_...` и не является
секретом. Положи на шлюз как `/etc/gateway/build-passport.conf` (после
сборки его можно оставить как справку).

```
# build-passport.conf - заполняет человек. СЕКРЕТОВ ЗДЕСЬ НЕТ.
HOSTNAME="gw1"
TZ="Europe/Moscow"
# сетевые карты: по MAC, имена wan/lan закрепляются Шагом 1.4
WAN_MAC="ПОДСТАВЬ_MAC_WAN"
LAN_MAC="ПОДСТАВЬ_MAC_LAN"
LAN_SUBNET="192.168.50.0/24"
LAN_GW_IP="192.168.50.1"
# способ выхода в интернет: dhcp (за роутером провайдера) или pppoe (Часть 9)
WAN_MODE="dhcp"
# VPS (если есть)
VPS_IP="ПОДСТАВЬ_IP_VPS"
VPS_SSH_USER="root"
# домен (если есть)
DOMAIN="ПОДСТАВЬ_ДОМЕН"
# диски: роли по Части 8, Шаг 8.0 (серийники, не буквы sdX!)
DISK_SYSTEM_SERIAL="ПОДСТАВЬ"
DISK_PHOTOS_SERIAL="ПОДСТАВЬ"
DISK_BACKUP_SERIAL="ПОДСТАВЬ"
# что собирать (yes/no)
WANT_VPS="yes"
WANT_IMMICH="yes"
WANT_PANEL="yes"
# уведомления в Telegram: yes - токен положит человек на точке С2
WANT_TELEGRAM="yes"
```

## 5. Часть Б - задание агенту (🤖)

Это текст, который ты даёшь агенту целиком в начале работы.

```
Ты собираешь домашний шлюз на Debian 13 по документации Debian-gateway-docs
(Части 0-9). Читай Часть 0 и соблюдай все её правила, в том числе: проверяй
вывод по "ОЖИДАЕТСЯ", не меняй команды и версии, не угадывай, перед правкой
файла делай бэкап, секреты (ключи, токены, пароли) не читай и не выводи.
Всё, что нужно подставить и не секрет, бери из /etc/gateway/build-passport.conf.

Режим работы:
1. Иди этапами С0-С6 из Части 10, раздел 6. Этап начинается с проверки
   входа (преполёт) и заканчивается проверкой результата.
2. Одна команда за раз. После каждой - краткая запись в
   /var/log/agent-build.log: время, этап, команда, результат (OK/FAIL).
3. При несовпадении "ОЖИДАЕТСЯ" - не продолжай, не импровизируй: открой
   "ЕСЛИ НЕ ТАК" этого шага или Часть 4 и сообщи о проблеме.
4. На точках останова (⛔ в разделе 6) остановись и напиши владельцу, что
   именно ему сделать. Продолжай только после слов "продолжай".
5. Перед ЛЮБОЙ перезагрузкой, правкой firewall, SSH, сетевых интерфейсов или
   дисков: убедись, что есть второй путь доступа (SSH из LAN и Tailscale) и
   есть бэкап правки. Не делай их внезапно.
6. Секреты: токен бота, пароль PPPoE, ключи WARP и VPS - не читай и не
   показывай. Файлы с ними - только root:root 600.
7. В конце: docs-drift, bootcheck, учения (Часть 4, раздел 13),
   контрольная перезагрузка. Результат - отчёт в формате раздела 9.
```

## 6. Этапы сборки и точки останова

Для каждого этапа: что вход, что делает агент, как проверить, где стоп.
Нумерация шагов - из Частей 1-9.

| Этап | Вход (преполёт) | Делает агент | Проверка | Остановка |
|---|---|---|---|---|
| **С0** Разведка (только чтение) | паспорт заполнен, `ssh agent@` работает | сверить ОС, MAC карт и линки, диски по серийникам, время, доступ к зеркалам Debian и GitHub, `ip_forward=0`, чужих nft-правил нет | всё совпало с паспортом | ⛔ любое несовпадение (не та карта, диск не найден, нет линка) |
| **С1** Часть 1, шаги 1.2-1.6 | С0 пройден | имена `wan`/`lan` **по MAC** (Шаг 1.4), сеть NetworkManager (1.5), **контрольная перезагрузка №1** (1.6) | после перезагрузки `wan`/`lan` на месте, LAN отвечает, SSH из LAN | ⛔ перед перезагрузкой: подтверждение владельца |
| **С2** Часть 1, шаги 1.7-1.12 | С1 пройден | sysctl, firewall с kill-switch загрузки, NAT, dnsmasq, dnscrypt-proxy, DNS-заворот, автообновления, перезагрузка №2 | итоговая проверка Части 1 (с клиента) | ⛔ владелец подключает тестовый клиент и подтверждает интернет |
| **С3** Часть 2, шаги 2.1-2.12 | С2 пройден | AmneziaWG (DKMS + заголовки), Tailscale, каталоги и `gateway.conf`, регистрация WARP, слоты, наборы, правила, фидер, оркестратор, `warp-pick` (шаг 2.13 - после VPS, на этапе С5) | проверки шагов 2.1-2.12 | ⛔ **С3.1:** ссылка входа Tailscale; ⛔ **С3.2:** перед запуском слота при первом конфиге - подтверждение что есть доступ по Tailscale и из LAN |
| **С4** Часть 2, шаги 2.14-2.16 и Часть 3 | С3 пройден | уведомления, `bootcheck`, SSH только по ключу, панель, бэкап конфигурации | тестовое сообщение пришло; вход по ключу в новом окне | ⛔ **С4.1:** владелец сам кладёт `tg.conf` и проверяет "Тест"; ⛔ **С4.2:** перед отключением паролей SSH |
| **С5** Часть 6 и 9, VPS | VPS есть, ключ `agent-vps` работает | базовая защита VPS, AWG-сервер, ключи, firewall (6.4), `ru4`, пиры шлюза (6.7), затем на шлюзе **шаг 2.13** (запасной слот и полоса VPS), Tailscale на VPS (6.9), устойчивость VPS; PPPoE при необходимости (Часть 9) | VPS отвечает по туннелю, полоса `vpn-amz` живая, итоговая проверка Части 2 | ⛔ **С5.1:** перед firewall VPS - держать второй сеанс SSH открытым или консоль хостера; ⛔ **С5.2:** PPPoE: пароль вносит владелец, переключение только со стражем-откатом |
| **С6** Части 5, 7, 8 | всё выше | пересадка пула WARP мимо `DME` (5.7), диски (8.1-8.5), Caddy и сайт (7), Immich (7.8-7.12), бэкапы (8.7), SMART (8.8), запасная флешка (8.11) | WARP на не-`DME` узле, Immich открывается по домену, снимок создан | ⛔ **С6.1:** перед `СТИРАЕТ ДИСК` (8.3) - серийник диска подтверждает владелец; ⛔ **С6.2:** перед 7.6 - DNS домена указывает на VPS |
| **Приёмка** | С0-С6 | `docs-drift`, `bootcheck`, учения (Часть 4, 13), контрольная перезагрузка | раздел 7 | отчёт владельцу |

**Почему остановки там, где они есть.** Это места, где ошибка отрезает доступ
(сеть, SSH, перезагрузка, firewall VPS), стирает данные (диски) или требует
твоего аккаунта (Tailscale, Telegram, DNS, PPPoE).

## 7. Приёмка и отзыв доступа

Работа закончена, когда **всё** из списка:

- [ ] `docs-drift.sh` без `✗`, расхождения в `≠` понятны и записаны (Часть 4).
- [ ] После контрольной перезагрузки: `bootcheck` зелёный, правило
      `boot-leak-ks` на месте, туннели подняты, WARP не на `DME`.
- [ ] Учения (Часть 4, раздел 13) пройдены: kill-switch держит.
- [ ] Из внешнего мира закрыто всё лишнее (Часть 7, Шаг 7.9; Часть 6,
      раздел "Безопасность VPS").
- [ ] Бэкап конфигурации сделан (Часть 3, раздел 6), снимок Immich создан.
- [ ] Отозван доступ агента: `agent` заблокирован, ключ `agent-vps` убран.
- [ ] Сменены пароли, которые светились (пароль root VPS из письма и т.п.).
- [ ] Клиентские устройства подключены и проверены.

## 8. Как проверить схему до боевого запуска

1. Подними **виртуальную машину** (VirtualBox, Proxmox) с двумя сетевыми
   картами: одна во "внешнюю" сеть, вторая во внутреннюю, и вторую ВМ-клиента.
2. Пройди всю схему как для боевого шлюза: чистый Debian, паспорт, задание
   агенту. VPS можно взять тестовый на пробный период.
3. Смотри, **на каком этапе агент спотыкается** и сколько раз ему пришлось
   вмешиваться. Результат "70-80% без тебя" - уже хорошо.
4. Каждую найденную проблему занеси так: симптом -> причина -> что дописать в
   документацию (в таблицу уроков Части 4 или в этап выше).
5. Прогони минимум **два раза** на свежей ВМ: единичный успех ничего не
   доказывает.

## 10. Грабли Стеллы, зашитые в этапы

Это не повтор Части 4, а то, что агент проверяет **заранее**, чтобы не повторить.

| Что было на Стелле | Как защищаемся в сборке |
|---|---|
| имя карты съехало после перестановки в слоте | имена `wan`/`lan` закрепляются по MAC в Шаге 1.4 и проверяются в С0 и С1 |
| окно утечки LAN в WAN при загрузке | kill-switch `boot-leak-ks` в forward ставится в Части 1, проверка в приёмке |
| активация конфига убила весь шлюз | `Table = off` дописывается `gw-warp-activate`; первый конфиг - только после С3.2 |
| `vpn-slot-up.sh` без `exit 0`, туннели `failed` после загрузки | скрипт берётся из Части 2 как есть, проверка после каждой перезагрузки (Часть 4, раздел 7) |
| застряли на `vpn-backup` | `PersistentKeepalive` на `vpn-main`, проверка в итоговой проверке Части 2 |
| таймер "включён", но не срабатывает (нет `--now`) | команды берутся из Частей как есть (где нужен немедленный запуск, там `--now`); после каждого этапа агент сверяет `systemctl list-timers` и `is-enabled` |
| `systemctl reload dnsmasq` вместо `restart` | команды из Частей используют `restart` |
| `sudo cmd < файл` отказывает | правило 18 Части 0 |
| команда с `www.` испортилась | правило 13 Части 0 |
| `sed -i '...a\'` задвоил строки | после любой вставки `grep -n` (правило 12) |
