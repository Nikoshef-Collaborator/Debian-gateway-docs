## Правила для ИИ-помощника (ОБЯЗАТЕЛЬНЫ во всех частях)

Если ты - ИИ и ведёшь человека по этим документам, соблюдай СТРОГО. Нарушение
любого правила может отрезать человеку интернет или доступ к шлюзу.

1. **ОДНА команда за раз.** Дай РОВНО ОДНУ команду и жди её вывод. Только потом
   следующую.
2. **Каждая команда - в своём блоке кода.** Человек копирует блок целиком.
   Две команды в одном блоке склеиваются при вставке и ломаются. Исключение -
   блоки `tee <<'EOF' ... EOF`: это одна команда, создающая файл.
3. **Сверяй вывод с "ОЖИДАЕТСЯ".** Не совпало - НЕ иди дальше, иди в
   "ЕСЛИ НЕ ТАК" этого шага.
4. **Не меняй команды.** Не "улучшай", не подставляй свои интерфейсы, адреса,
   версии. Всё, что человек должен вписать сам, помечено словом
   `ПОДСТАВЬ_...` и знаком ⛔.
5. **На "⛔ СТОП" - остановись**, дальше только после подтверждения.
6. **Не уверен - спроси или дай диагностическую команду. Не угадывай.**
   Если симптом не подходит ни под один раздел Части 4 - так и скажи.
7. **Длинный вывод - в файл через `tee`**, например
   `... 2>&1 | tee /tmp/check.log`. Терминал обрезает начало.
8. **Всегда называй машину**, на которой выполнять команду: шлюз, VPS или
   ПК (PowerShell). Человек легко вставляет команду не в то окно.
9. **Секреты не в чат.** Приватные ключи, `PresharedKey`,
   `HeaderProtectionKey`, токены ботов, пароли, клиентские `.conf` целиком -
   никогда не проси прислать и не выводи. Для проверки конфига проси вывод с
   вырезанными ключами.
10. **Работает - не трогай.** Не предлагай переделывать исправную часть без
    конкретной причины.
11. **Перед правкой файла - бэкап** (`cp файл файл.bak-ЧТО`), бэкапы dnsmasq -
    ВНЕ `/etc/dnsmasq.d/` (dnsmasq читает там все файлы, любое расширение).
12. **После вставки строк через `sed -i '...a\'` - проверь `grep -n`.** Эта
    команда не идемпотентна: повторный запуск задваивает строки.
13. **Домены с `www.` в начале** некоторые чаты превращают в ссылку и портят
    команду. В командах проверки бери домен без `www.`.
14. **Не предлагай VLESS, sing-box, tun2socks** и подобные стеки - они
    сознательно удалены. Протокол туннелей - AmneziaWG.
15. **Диагностику начинай с железа.** Обрыв "у всех сразу" - сначала линк и
    кабели (`journalctl -k | grep "Link is"`, Часть 4 раздел 00.4), потом
    туннели и правила.
16. **Ошибки загрузки видны только при загрузке.** Поправил юнит или скрипт,
    который работает при старте, - предложи человеку контрольную
    перезагрузку в удобное время и проверку по Части 4, раздел 7.
17. **Документация может расходиться с живой системой.** Перед правкой
    смотри живой файл (`cat`, `grep -n`), а не только этот текст.

**Человеку:** выполняй по одной команде, весь вывод копируй помощнику. Ключи
и пароли из вывода вырезай.

## Как устроен шлюз (мысленная модель)

Шлюз - обычный ПК с Debian 13 и двумя сетевыми картами:
- `wan` - в интернет (адрес по DHCP от PON-терминала или роутера провайдера);
- `lan` - в дом (статический `192.168.50.1`, раздаёт DHCP и DNS).

Имена `wan`/`lan` назначаются по MAC-адресу (Часть 1), поэтому не зависят
от слота PCI.

### Главная идея: инверсная маршрутизация

**По умолчанию весь трафик домашних устройств уходит в туннель WARP.
Напрямую через провайдера идут только исключения** - российские сайты и
адреса, а также серверы самих туннелей.

Почему не наоборот (напрямую по умолчанию, в туннель только
заблокированное): списки блокировок не успевают за реальностью, каждую новую
блокировку приходится ловить руками. Список "что российское" намного
стабильнее, и его ведёт сообщество.

### Цепочка, на которой держится всё

```
1. домен   -> dnsmasq узнаёт IP домена и кладёт его в "набор" (nftset)
2. набор   -> nftables ставит пакету к этому IP "метку" (fwmark)
3. метка   -> ip rule по метке выбирает таблицу маршрутов
4. таблица -> таблица говорит, через какой интерфейс выпустить пакет
5. выход   -> пакет уходит в WARP, в VPS или напрямую
```

Формула: **домен -> набор -> метка -> таблица -> выход.**

⚠️ Маршрутизация работает **по IP, а не по домену.** Если два сайта живут на
одном IP (типично для Cloudflare и других CDN), они всегда идут одной
полосой. Развести их невозможно.

### Полосы

| Метка | Куда | Что туда попадает |
|---|---|---|
| нет метки | таблица 100 -> `vpn-main` (WARP), запасной - `vpn-backup` | всё, что не попало в исключения |
| `0x100` | `main` -> напрямую через `wan` | российские домены и подсети, адреса серверов туннелей, Twitch |
| `0x200` | таблица 200 -> `vpn-amz` (свой VPS) | ИИ-сервисы, голосовые подсети мессенджеров, ручной список "через VPS" |

Наборы в таблице `ip gwroute` и порядок правил в цепочке `gwmark`:

| № | Набор | Действие | Кто наполняет |
|---|---|---|---|
| 1 | `endpoints` | метка 0x100 (напрямую) | `vpn-slot-up.sh`, `gw-routing-restore.sh` |
| 2 | `ru_cidr` | 0x100 | `gw-feeder.sh`, раз в сутки |
| 3 | `ru_direct` | 0x100 | dnsmasq: зоны `.ru/.su/.рф` + community-список |
| 4 | `cf_warp` | сброс 0x100 -> 0 (обратно в WARP) | статика в `/etc/gwroute.nft` (диапазоны Cloudflare) |
| 5 | `warp_force` | сброс 0x100 -> 0 | dnsmasq: `06-warp-force.conf` |
| 6 | `zapret_direct` | 0x100 | dnsmasq: `03-yt-direct.conf`, `05-gw-manual.conf` |
| 7 | `ai_direct` | 0x200 (VPS) | dnsmasq: `04-ai-direct.conf`, `07-vps-manual.conf`, `05-gw-manual.conf` |
| 8 | `voice_direct` | 0x200 | `gw-feeder.sh` |

**`meta mark set` - не вердикт.** Пакет проходит цепочку до конца, и
**побеждает последнее совпавшее правило.** Поэтому порядок важен:
`cf_warp` и `warp_force` стоят после российских наборов и возвращают пакет
в WARP, а ИИ-полоса стоит последней и перекрывает всё.

### Кто чем управляет

| Слой | Хозяин | Где живёт |
|---|---|---|
| адрес на `wan` | NetworkManager | профиль `Wired connection 1` |
| адрес на `lan` | юнит `gw-lan` | `/usr/local/sbin/gw-lan.sh` |
| firewall входа в шлюз | юнит `gw-fw` | `/etc/gw-fw.nft` |
| NAT LAN -> wan | юнит `gw-nat` | `/usr/local/sbin/gw-nat.sh` |
| заворот DNS клиентов на шлюз | юнит `gw-dnsredirect` | `/etc/gw-dnsredirect.nft` |
| наборы, метки, NAT туннелей, ip rule | юнит `gw-routing` | `/etc/gwroute.nft`, `gw-routing-restore.sh` |
| туннели | `vpn-slot@<слот>` | `/etc/gateway/tunnels/<слот>.conf` |
| таблица 100 (дефолт) | `gw-orchestrator.timer`, раз в 30 с; WARP умер -> сам запускает `warp-rotate` | `gw-orchestrator.sh` |
| таблица 200 (VPS) | kill-switch drop-in слота `vpn-amz` | `vpn-slot@vpn-amz.service.d/` |
| выбор WARP-конфига | `warp-pick.sh`: при загрузке и по `warp-rotate.timer` раз в 5-7 ч | пул `/etc/warp/pool`, `/etc/gateway/pool` |
| самописец обрывов | `netwatch.service` | `/var/log/netwatch.log` (Часть 4, раздел 12) |
| списки РФ, голос | `gw-feeder.timer`, раз в сутки | `gw-feeder.sh` |
| Docker, Tailscale | сами себе | таблицы `ip nat`, `ip filter` |

Два железных правила:
- **Одной таблицей маршрутов управляет ровно один процесс.** Два хозяина =
  маршрут прыгает туда-сюда.
- **Никогда не пиши `flush ruleset`** и не трогай таблицу `ip nat`: там
  живут Docker и Tailscale. Каждый наш юнит пересоздаёт только свою таблицу.

### Kill-switch

Если все туннели дефолтной полосы мертвы, таблица 100 уходит в `blackhole`, а
**не** напрямую. Лучше заметный обрыв, чем тихий выход всего дома в открытую.
Для таблицы 200 то же самое: ИИ-сервисы без VPS не работают, но и не светят
домашний IP.

## Словарь

| Термин | Что значит |
|---|---|
| **WARP** | бесплатный туннель Cloudflare (WireGuard). Здесь - основной выход |
| **AmneziaWG (AWG)** | WireGuard с маскировкой от DPI. Модуль ядра + `awg`, `awg-quick` |
| **слот** | интерфейс туннеля: `vpn-main` (WARP), `vpn-backup` (запасной), `vpn-amz` (полоса VPS) |
| **пул** | папка с запасными конфигами WARP, из которой `warp-pick` выбирает живой |
| **handshake** | рукопожатие туннеля. Свежее (< 3 мин) = туннель жив |
| **endpoint** | адрес сервера туннеля. Он всегда должен идти напрямую, иначе петля |
| **ТСПУ** | оборудование DPI провайдера, которое режет и замедляет трафик |
| **nftset** | директива dnsmasq: "IP этого домена положи в такой набор nftables" |
| **полоса** | путь выхода трафика: WARP, напрямую или VPS |
| **Чебурнет** | профиль клиента на VPS: российские адреса уходят через домашний IP (Часть 6) |

## Почему так, а не иначе (короткая история решений)

- **zapret2 снят с обоих шлюзов.** Он лечит только блокировку установки
  соединения, а видео и стримы душат по IP уже после неё. Месяцы подбора
  стратегий отодвигали обрыв YouTube с 6 до ~14 минут, но не убирали его.
  Через туннель всё работает. Набор `zapret_direct` остался под Twitch: тот
  на прямом канале сейчас работает и через WARP идти не обязан.
- **Модуль ядра AmneziaWG вместо `amneziawg-go`.** Конфиги поднимает штатный
  `awg-quick` со строкой `Table = off`. Маршрутами управляют наши скрипты, а
  не `awg-quick`. Если модуля нет, `awg-quick` сам откатывается на
  `amneziawg-go` - это работает, но тогда слоты поднимаются **только через
  systemd** (`systemctl restart vpn-slot@...`), иначе systemd убьёт процесс
  туннеля вместе с чужой службой.
- **Самовосстановление слотов.** `vpn-slot@` с `Restart=on-failure`: упавший
  при старте туннель повторяется через 30 с, а не лежит до ручного запуска.
  Ротация WARP по таймеру переводит дом на `vpn-backup` на время перебора,
  поэтому смена конфига проходит без простоя.
- **WARP основной, свой VPS - резерв.** Умер WARP-конфиг - дом за секунды
  уходит на VPS, а оркестратор сам запускает перебор WARP и через минуту-две
  возвращает дом обратно (раньше дом мог часами сидеть на VPS до таймера
  ротации). Если WARP закроют насовсем - порядок каскада меняется одной
  строкой (`VPN_CASCADE_ORDER`), заметка об этом в шапке оркестратора.
- **YouTube в `warp_force`.** Часть видеосерверов стоит кэшем у российских
  провайдеров с российскими IP и через `ru_cidr` утекала напрямую, где видео
  режут. `warp_force` перебивает `ru_cidr` (Часть 4, 1.11).
- **Живость туннеля - по возрасту handshake, а не по ping/curl.** Внешние
  пробы дают ложные провалы под нагрузкой, и при единственной цели проверки
  kill-switch может залипнуть навсегда.
- **Списки РФ:** домены - itdoginfo/allow-domains (`Russia/outside-dnsmasq-nfset.lst`),
  подсети - jinndi/geoip-ru-ipset (`ru-no-blocked.txt`, из него уже вычтены
  заблокированные диапазоны), голос - itdoginfo `Subnets/IPv4`. Обновляются
  ежедневно.
- **ИИ-сервисы не через WARP:** OpenAI и Anthropic отвечают 403 на адреса
  Cloudflare. Нужен чистый выход - свой VPS (полоса 0x200).
- **Платный Amnezia Premium выведен.** Его серверы точечно блокировали волнами
  (лето 2026), конфиги приходилось перевыпускать. Свой VPS дешевле и под
  контролем.
- **DNS двумя путями.** DoH к AdGuard напрямую, DNSCrypt к AdGuard на
  другом адресе - через туннель. ТСПУ режет DoH/DoT (осень 2026), а без DNS
  дом "без интернета" даже при живых туннелях.
- **IPv6 выключен полностью.** Вся схема IPv4. Иначе IPv6 утекает мимо полос.
