## 1. Куда идёт домен и какой путь работает

**В каком наборе домен** (домен без `www.`):

```
D=example.com; for ip in $(dig +short $D @127.0.0.1 | grep -E '^[0-9.]+$'); do echo "== $ip"; for s in endpoints ru_cidr ru_direct cf_warp warp_force zapret_direct ai_direct voice_direct; do sudo nft get element ip gwroute $s "{ $ip }" >/dev/null 2>&1 && echo "  $s"; done; done
```

Как читать (порядок важен - побеждает последнее совпадение, Часть 0):
- ни одного набора -> WARP;
- `ru_cidr`/`ru_direct` -> напрямую, **если ниже нет** `cf_warp`/`warp_force`;
- `cf_warp` или `warp_force` -> обратно в WARP;
- `zapret_direct` -> напрямую;
- `ai_direct`/`voice_direct` -> через VPS.

**Какой путь вообще работает** - три запроса с самого шлюза, по одному:

```
curl -sS -o /dev/null -w "direct: %{http_code} %{time_total}s\n" --max-time 15 https://example.com/
```

```
curl -sS -o /dev/null -w "warp: %{http_code} %{time_total}s\n" --max-time 15 --interface vpn-main https://example.com/
```

```
curl -sS -o /dev/null -w "vps: %{http_code} %{time_total}s\n" --max-time 15 --interface vpn-amz https://example.com/
```

- `000` и таймаут - путь закрыт;
- любой HTTP-код, даже `403`, - связь есть (403 на WARP у ИИ-сервисов = гео-блок
  адресов Cloudflare, нужен VPS).

Выбор полосы по результату:

| direct | warp | vps | Куда класть |
|---|---|---|---|
| работает | любой | любой | ничего не делать или напрямую |
| `000` | работает | любой | WARP (если домен российский - `06-warp-force`) |
| `000` | `000` или `403` | работает | VPS (`07-vps-manual`) |

## 2. Перенести домен в другую полосу

⚠️ Маршрутизация **по IP**. Если сайт делит IP с другими (Cloudflare,
CDN), все сайты на этом IP пойдут одной полосой. Реальный случай: домен
переложили на VPS - и соседний сайт на том же IP Cloudflare уехал туда же.
Развести их нельзя.

⚠️ После правки любого файла в `/etc/dnsmasq.d/`: сначала `sudo dnsmasq --test`,
потом **`restart`** (не `reload`). Потом на клиенте сброс кэша DNS
(`ipconfig /flushdns` на Windows) и новая вкладка.

### 2.1 Ручные списки (основной способ)

| Файл | Набор | Когда |
|---|---|---|
| `/etc/dnsmasq.d/06-warp-force.conf` | `warp_force` | всегда через WARP, даже `.ru` (российский сайт, который режется напрямую) |
| `/etc/dnsmasq.d/07-vps-manual.conf` | `ai_direct` | через VPS: не пускает WARP и режется напрямую |
| `/etc/dnsmasq.d/03-yt-direct.conf` | `zapret_direct` | всегда напрямую (сервис нормально работает без обхода) |

Пример - добавить домен в `07-vps-manual.conf`:

```
echo 'nftset=/example.com/4#ip#gwroute#ai_direct' | sudo tee -a /etc/dnsmasq.d/07-vps-manual.conf
```

```
sudo dnsmasq --test
```

```
sudo systemctl restart dnsmasq
```

Прогреть, чтобы IP сразу попал в набор:

```
dig +short example.com @127.0.0.1
```

Проверить - запусти команду из раздела 1, домен должен быть в `ai_direct`.

> Сайт грузится частично (нет стилей, картинок)? Он тянет файлы с **другого**
> домена (CDN). Открой в браузере F12 -> вкладка "Сеть", найди запросы с
> ошибкой и добавь их домен тоже.

Удалить домен из файла (пример):

```
sudo sed -i '/\/example\.com\//d' /etc/dnsmasq.d/07-vps-manual.conf
```

затем `--test` и `restart`. IP, уже лежащий в наборе, уйдёт после
перезагрузки шлюза или после `sudo nft flush set ip gwroute ai_direct` и
`restart` dnsmasq (набор наполнится заново по запросам).

### 2.2 Перенос доменов и групп скриптом (`gw-domain-move`)

Состояние хранится в `/etc/gateway/lane-state.conf` (`домен=полоса`), из него
пересобирается `05-gw-manual.conf`. Группа - имя файла из
`/etc/gateway/service-groups/` (например `youtube`, его качает фидер).

Полосы скрипта: `direct` (набор `zapret_direct`), `amz` (набор `ai_direct`,
то есть VPS), `warp` - убрать из ручного состояния.

> ⚠️ `warp` здесь значит "снять ручное назначение", а не "принудительно в
> WARP". Российский домен после `warp` останется напрямую. Для
> принудительного WARP - `06-warp-force.conf` (2.1).

```
sudo tee /usr/local/sbin/gw-domain-move.sh > /dev/null <<'EOF'
#!/bin/bash
# gw-domain-move.sh <домен|группа> <warp|direct|amz>
# Обновляет lane-state.conf и пересобирает 05-gw-manual.conf.
set -u
STATE="/etc/gateway/lane-state.conf"
[ "$(id -u)" -eq 0 ] || { echo "запускай через sudo"; exit 1; }
TARGET="${1:-}"; LANE="${2:-}"
[ -z "$TARGET" ] || [ -z "$LANE" ] && { echo "Использование: $0 <домен|группа> <warp|direct|amz>"; exit 1; }
case "$LANE" in warp|direct|amz) ;; *) echo "ERROR: полоса только warp, direct, amz"; exit 1 ;; esac
touch "$STATE"
grep -v "^${TARGET}=" "$STATE" > "${STATE}.tmp" 2>/dev/null || : > "${STATE}.tmp"
[ "$LANE" != "warp" ] && echo "${TARGET}=${LANE}" >> "${STATE}.tmp"
mv "${STATE}.tmp" "$STATE"
/usr/local/sbin/gw-domain-rebuild.sh
EOF
```

```
sudo tee /usr/local/sbin/gw-domain-rebuild.sh > /dev/null <<'EOF'
#!/bin/bash
# gw-domain-rebuild.sh - пересобирает 05-gw-manual.conf из lane-state.conf
# и свежих service-groups. Вызывают gw-domain-move.sh и gw-feeder.sh.
# Перенесённый домен вычищается из 03/04: иначе он остаётся в двух наборах,
# и полоса VPS (метка 0x200 ставится последней) перебивает перенос.
set -u
STATE="/etc/gateway/lane-state.conf"
MANUAL_CONF="/etc/dnsmasq.d/05-gw-manual.conf"
YT_CONF="/etc/dnsmasq.d/03-yt-direct.conf"
AI_CONF="/etc/dnsmasq.d/04-ai-direct.conf"
GROUPS_DIR="/etc/gateway/service-groups"
TABLE="gwroute"
[ "$(id -u)" -eq 0 ] || { echo "запускай через sudo"; exit 1; }
touch "$STATE"
: > "${MANUAL_CONF}.new"
while IFS='=' read -r target lane; do
    [ -z "$target" ] && continue
    case "$lane" in
        direct) SET="zapret_direct" ;;
        amz)    SET="ai_direct" ;;
        *) continue ;;
    esac
    DOMAINS=()
    if [ -f "$GROUPS_DIR/$target.txt" ]; then
        while IFS= read -r d; do
            [ -z "$d" ] && continue
            DOMAINS+=("$d")
        done < "$GROUPS_DIR/$target.txt"
    else
        DOMAINS=("$target")
    fi
    for d in "${DOMAINS[@]}"; do
        # вычистить из 03/04 при каждой пересборке
        for f in "$YT_CONF" "$AI_CONF"; do
            [ -f "$f" ] && sed -i "\#/${d}/#d" "$f"
        done
        echo "nftset=/${d}/4#ip#${TABLE}#${SET}" >> "${MANUAL_CONF}.new"
    done
done < "$STATE"
mv "${MANUAL_CONF}.new" "$MANUAL_CONF"
if dnsmasq --test 2>&1 | grep -qi "syntax check OK"; then
    systemctl restart dnsmasq
    cnt=$(grep -c '^nftset=' "$MANUAL_CONF" 2>/dev/null || echo 0)
    echo "OK: пересобрано, $cnt записей в $MANUAL_CONF"
    exit 0
else
    echo "ERROR: dnsmasq --test не прошёл, dnsmasq НЕ перезапущен"
    exit 1
fi
EOF
```

```
sudo chmod 755 /usr/local/sbin/gw-domain-move.sh /usr/local/sbin/gw-domain-rebuild.sh
```

Пример - YouTube целиком напрямую и обратно:

```
sudo /usr/local/sbin/gw-domain-move.sh youtube direct
```

```
sudo /usr/local/sbin/gw-domain-move.sh youtube warp
```

**ОЖИДАЕТСЯ:** `OK: пересобрано, N записей`.

> Отличие от старой версии: скрипт больше не вычищает домены из `03`/`04`
> через `sed`. Дубль в двух файлах не ломает dnsmasq, а `sed` по имени домена
> задевал похожие строки.

## 3. WARP-конфиги и слоты

Пул: `/etc/gateway/pool/` (сюда кладутся новые) и `/etc/warp/pool/`.
`warp-pick` берёт из обоих. Слоты: `vpn-main` (WARP), `vpn-backup`,
`vpn-amz`.

### 3.1 Скрипты пула

Добавить конфиг текстом (для панели, раздел 5):

```
sudo tee /usr/local/sbin/gw-pool-add.sh > /dev/null <<'EOF'
#!/bin/bash
# gw-pool-add.sh <имя> <текст_конфига> - сохранить конфиг в пул
set -u
[ "$(id -u)" -eq 0 ] || { echo "запускай через sudo"; exit 1; }
POOL="/etc/gateway/pool"; RAW="${1:-}"; BODY="${2:-}"
NAME=$(basename -- "$RAW" | tr -cd 'A-Za-z0-9._-')
[ -n "$NAME" ] || NAME="manual-$(date +%Y%m%d-%H%M%S)"
case "$NAME" in *.conf) ;; *) NAME="${NAME}.conf" ;; esac
[ -n "$BODY" ] || { echo "ERROR: пустой текст конфига"; exit 1; }
printf '%s' "$BODY" | grep -q '\[Interface\]' || { echo "ERROR: нет [Interface] - это не конфиг WG/AWG"; exit 1; }
mkdir -p "$POOL"; DST="${POOL}/${NAME}"
[ -f "$DST" ] && cp "$DST" "${DST}.bak-$(date +%Y%m%d-%H%M%S)"
printf '%s\n' "$BODY" > "$DST"; chmod 600 "$DST"
logger -t gw-pool "добавлен конфиг: $NAME"; echo "Добавлено в пул: $NAME"
/usr/local/sbin/gw-pool-refresh-entities.sh
EOF
```

Тест одного конфига на временном интерфейсе (боевые слоты не трогает):

```
sudo tee /usr/local/sbin/gw-warp-test.sh > /dev/null <<'EOF'
#!/bin/bash
# gw-warp-test.sh <файл_в_pool> - рукопожатие, пинг, скорость на интерфейсе warptest
set -u
[ "$(id -u)" -eq 0 ] || { echo "запускай через sudo"; exit 1; }
SRC="/etc/gateway/pool/${1:-}"
[ -f "$SRC" ] || { echo "Использование: $0 <файл_в_pool>"; exit 1; }
TESTIF=warptest; TESTCONF="/etc/gateway/tunnels/${TESTIF}.conf"
TEST_URL="https://speed.cloudflare.com/__down?bytes=5000000"
cleanup(){ awg-quick down "$TESTCONF" 2>/dev/null; rm -f "$TESTCONF"; }
trap cleanup EXIT
awk '
/^[[:space:]]*(DNS|Table|PreUp|PostUp|PreDown|PostDown)[[:space:]]*=/ { next }
/^[[:space:]]*(Address|AllowedIPs)[[:space:]]*=/ {
    eq=index($0,"="); key=substr($0,1,eq-1); n=split(substr($0,eq+1),p,","); out=""
    for(i=1;i<=n;i++){ gsub(/^[ \t]+|[ \t]+$/,"",p[i]); if(p[i]!~/:/) out=(out==""?p[i]:out", "p[i]) }
    if(out!="") print key"= "out; next }
{ print }' "$SRC" > "$TESTCONF"
sed -i '/^\[Interface\]/a Table = off' "$TESTCONF"; chmod 600 "$TESTCONF"
awg-quick up "$TESTCONF" >/dev/null 2>&1 || { echo "РЕЗУЛЬТАТ: awg-quick up ошибка -> конфиг мёртв"; exit 1; }
# без keepalive рукопожатие само не стартует - пинаем пакетом и меряем пинг
ping_avg=$(ping -I "$TESTIF" -c3 -W3 1.1.1.1 2>/dev/null | awk -F'/' '/rtt|round-trip/{print $5}')
hs=$(awg show "$TESTIF" 2>/dev/null | awk '/latest handshake/{$1=$2=""; print}')
[ -z "$hs" ] && { echo "РЕЗУЛЬТАТ: нет рукопожатия -> конфиг мёртв"; exit 1; }
bps=$(curl -o /dev/null -s --interface "$TESTIF" -m 20 -w '%{speed_download}' "$TEST_URL" 2>/dev/null | tr ',' '.')
echo "РЕЗУЛЬТАТ: OK"; echo "  рукопожатие:$hs"; echo "  пинг: ${ping_avg:-н/д} ms"
echo "  скорость: $(awk "BEGIN{printf \"%.1f\", ${bps:-0}/1048576}") MB/s"
EOF
```

Поставить конфиг из пула в слот (бэкап старого, правка формата, рестарт):

```
sudo tee /usr/local/sbin/gw-warp-activate.sh > /dev/null <<'EOF'
#!/bin/bash
# gw-warp-activate.sh <файл_в_pool> <vpn-main|vpn-backup|vpn-amz>
set -u
[ "$(id -u)" -eq 0 ] || { echo "запускай через sudo"; exit 1; }
POOLFILE="${1:-}"; SLOT="${2:-}"
case "$SLOT" in vpn-main|vpn-backup|vpn-amz) ;; *) echo "Использование: $0 <файл_в_pool> <vpn-main|vpn-backup|vpn-amz>"; exit 1 ;; esac
SRC="/etc/gateway/pool/${POOLFILE}"; DST="/etc/gateway/tunnels/${SLOT}.conf"
[ -f "$SRC" ] || { echo "ERROR: нет в пуле: $SRC"; exit 1; }
[ -f "$DST" ] && cp "$DST" "${DST}.bak-$(date +%Y%m%d-%H%M%S)"
# убрать DNS= (DNS на шлюзе - dnsmasq; awg-quick падает без resolvconf),
# Pre/PostUp (чужие скрипты), IPv6-адреса (IPv6 выключен - awg-quick up падает)
awk '
/^[[:space:]]*(DNS|PreUp|PostUp|PreDown|PostDown)[[:space:]]*=/ { next }
/^[[:space:]]*(Address|AllowedIPs)[[:space:]]*=/ {
    eq=index($0,"="); key=substr($0,1,eq-1); n=split(substr($0,eq+1),p,","); out=""
    for(i=1;i<=n;i++){ gsub(/^[ \t]+|[ \t]+$/,"",p[i]); if(p[i]!~/:/) out=(out==""?p[i]:out", "p[i]) }
    if(out!="") print key"= "out; next }
{ print }' "$SRC" > "$DST"
chmod 600 "$DST"
# Table: vpn-amz сам ведёт таблицу 200, остальные - off (иначе awg-quick
# перехватит весь трафик шлюза своим ip rule)
TBL=off; [ "$SLOT" = "vpn-amz" ] && TBL=200
sed -i '/^[[:space:]]*Table[[:space:]]*=/d' "$DST"
sed -i "/^\[Interface\]/a Table = $TBL" "$DST"
# keepalive обязателен: оркестратор судит о живости по свежести рукопожатия
grep -qE '^[[:space:]]*PersistentKeepalive' "$DST" || sed -i '/^\[Peer\]/a PersistentKeepalive = 25' "$DST"
systemctl restart "vpn-slot@${SLOT}.service"; sleep 3
ping -c2 -W2 -I "$SLOT" 1.1.1.1 >/dev/null 2>&1
hs=$(awg show "$SLOT" 2>/dev/null | awk '/latest handshake/{$1=$2=""; print}')
[ -n "$hs" ] && echo "OK: $SLOT из $POOLFILE, рукопожатие:$hs" || echo "WARNING: $SLOT перезапущен, рукопожатия нет - проверь конфиг"
EOF
```

Статус слотов и очистка слота:

```
sudo tee /usr/local/sbin/gw-slot-status.sh > /dev/null <<'EOF'
#!/bin/bash
# gw-slot-status.sh - конфиг, служба и рукопожатие каждого слота
for SLOT in vpn-main vpn-backup vpn-amz; do
    conf="/etc/gateway/tunnels/${SLOT}.conf"; echo "-> $SLOT"
    if [ -f "$conf" ]; then
        echo "    конфиг:  есть (Endpoint: $(awk -F'=' '/^[[:space:]]*Endpoint/{gsub(/[[:space:]]/,"",$2);print $2;exit}' "$conf"))"
    else echo "    конфиг:  НЕТ"; fi
    echo "    служба:  $(systemctl is-active "vpn-slot@${SLOT}.service" 2>/dev/null)"
    if ip link show "$SLOT" >/dev/null 2>&1; then
        hs=$(awg show "$SLOT" 2>/dev/null | awk '/latest handshake/{$1=$2="";print;exit}')
        echo "    рукопожатие:${hs:- нет}"
    else echo "    интерфейс: не поднят"; fi
done
EOF
```

### 4.1 Ночное автообновление (`update.sh`)

Каждую ночь в 4:00 (плюс до 10 минут случайно) скрипт:

1. ставит обновления пакетов (`apt-get upgrade`);
2. если пакеты требуют перезагрузки (есть `/var/run/reboot-required`, обычно
   после нового ядра) - пишет в Telegram и через минуту перезагружает шлюз;
3. сравнивает версию Immich с последней на GitHub и, если вышла новая,
   пишет в Telegram. Сам Immich не обновляет - это делается руками (Часть 7).

Он работает вместе с `unattended-upgrades` из Части 1 (Шаг 1.11): тот
ставит обновления безопасности, этот - всё остальное и перезагружает.

⚠️ Перезагрузка автоматическая. После неё смотри отчёт `bootcheck` в
Telegram. Если туннели не поднялись - первым делом проверь модуль AmneziaWG
под новым ядром (команды выше, в разделе 4).

```
sudo tee /usr/local/sbin/update.sh > /dev/null <<'EOF'
#!/bin/bash
# update.sh - обновление системы и проверка новой версии Immich.
# Запускается в 4:00 через update.timer.
#   1. apt upgrade; если нужна перезагрузка (новое ядро) - перезагрузка
#   2. проверка новой версии Immich -> уведомление в Telegram
#   Все результаты -> Telegram

set -u
LOG="/var/log/update-system.log"
TG="/usr/local/sbin/tg-notify.sh"

log() { echo "[$(date '+%F %T')] $*" | tee -a "$LOG"; }

log "=== Старт обновления ==="

# --- 1. apt upgrade ---
log "apt update..."
apt-get update -qq 2>&1 | tee -a "$LOG"

UPGRADABLE=$(apt list --upgradable 2>/dev/null | grep -v "^Listing" | wc -l)
log "Доступно обновлений: $UPGRADABLE"

if [ "$UPGRADABLE" -gt 0 ]; then
    log "apt upgrade..."
    DEBIAN_FRONTEND=noninteractive apt-get upgrade -y -qq 2>&1 | tee -a "$LOG"

    # нужна ли перезагрузка (обычно - обновилось ядро)
    if [ -f /var/run/reboot-required ]; then
        KERNEL_NEW=$(uname -r)
        log "Обновлено ядро — планируем перезагрузку через 1 минуту"
        "$TG" "Обновление системы" "Установлено $UPGRADABLE обновлений ✅
Обновлено ядро → перезагрузка через 1 минуту" warn
        sleep 60
        log "Перезагрузка..."
        reboot
    else
        log "Перезагрузка не требуется"
        "$TG" "Обновление системы" "Установлено $UPGRADABLE обновлений ✅
Перезагрузка не требуется" info
    fi
else
    log "Система актуальна"
fi

# --- 2. Проверка версии Immich ---
log "Проверка версии Immich..."

# текущая версия - у запущенного контейнера
CURRENT=$(curl -s http://localhost:2283/api/server/version 2>/dev/null | grep -oE '[0-9]+' | paste -sd '.' | awk '{print "v"$0}')

# последняя версия - из GitHub API
LATEST=$(curl -s --max-time 10 \
    https://api.github.com/repos/immich-app/immich/releases/latest 2>/dev/null | \
    grep '"tag_name"' | grep -oE 'v[0-9]+\.[0-9]+\.[0-9]+' | head -1)

log "Immich: текущая=$CURRENT последняя=$LATEST"

if [ -n "$LATEST" ] && [ -n "$CURRENT" ] && [ "$LATEST" != "$CURRENT" ]; then
    "$TG" "Immich: доступно обновление" "Текущая версия: $CURRENT
Новая версия:   $LATEST

Как обновить — см. FAQ в документации." warn
else
    log "Immich актуален ($CURRENT)"
fi

log "=== Обновление завершено ==="
EOF
```

```
sudo chmod 755 /usr/local/sbin/update.sh
```

```
sudo tee /etc/systemd/system/update.service > /dev/null <<'EOF'
[Unit]
Description=System update (apt + zapret2 + Immich check)
After=network-online.target
Wants=network-online.target

[Service]
Type=oneshot
ExecStart=/usr/local/sbin/update.sh
StandardOutput=journal
StandardError=journal
EOF
```

```
sudo tee /etc/systemd/system/update.timer > /dev/null <<'EOF'
[Unit]
Description=Run system update at 4:00 daily

[Timer]
OnCalendar=*-*-* 04:00:00
RandomizedDelaySec=10min
Persistent=true

[Install]
WantedBy=timers.target
EOF
```

`--now` обязателен: без него таймер включится только со следующей загрузки.

```
sudo systemctl daemon-reload && sudo systemctl enable --now update.timer
```

```
systemctl list-timers update.timer --no-pager
```

**ОЖИДАЕТСЯ:** строка с ближайшим запуском около 4:00.

Журнал: `/var/log/update-system.log`.

> Почему `apt-get upgrade`, а не `full-upgrade`: ночью без присмотра он не
> удаляет пакеты. Если новое ядро "отложено" (kept back) - видно так:
> `apt-get -s upgrade | grep -A4 -i 'kept back'`; тогда ставь руками
> командой из раздела 4.

>   `config.yaml` через `nano` или переноси файл `scp`;
> - доступ к панели ограничен твоей сетью Tailscale. Пароль на вход - в
